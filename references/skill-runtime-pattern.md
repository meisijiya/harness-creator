# 技能运行时模式

当你想把可复用的代理行为打包为技能，而不是在每个仓库中重复冗长的指令时，使用本模式。

## 什么应该放进技能

- 跨项目适用的可复用工作流。
- 特定领域的决策程序。
- 代理应按需加载的模板、清单与参考材料。
- 稳定且可安全运行的小型辅助脚本。

## 什么不应该放进技能

- 应放在目标仓库中的项目特定架构事实。
- 机密、令牌、私有 URL 或用户专属凭据。
- 代理在行动前必须通读的大型手册。
- 具有破坏性副作用的命令，除非已明确记录并要求用户显式批准。

## 运行时形态

生产级技能应采用渐进式披露：

1. `SKILL.md` 的 frontmatter 说明技能应在何时触发。
2. 正文给出最短的可靠工作流。
3. `references/` 存放仅在相关时才加载的深入材料。
4. `templates/` 存放可复制的产物。
5. `evals/` 记录代表性的质量检查。

## 设计规则

- 入口文件保持简洁，可快速浏览。
- 优先使用具体清单，而非抽象建议。
- 链接每个被引用的随附文件并验证其存在。
- 安装说明须明确仓库、技能名称与目标代理。
- 将脚本视为可选的辅助工具，而非隐藏行为。

## 验证清单

- [ ] `SKILL.md` 存在且 frontmatter 有效。
- [ ] 每个被引用的文件都存在于技能目录内。
- [ ] 模板可安全复制到目标仓库。
- [ ] 安装命令已通过 `skills add --list` 或等效方式测试。
- [ ] 技能不依赖私有的本地路径。
