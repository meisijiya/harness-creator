# 产物落点的 git 跟踪对齐（一次性）

**触发**：harness-creator「第一步」对齐阶段，写盘前完成，**每个项目只询问一次**。这是本技能独占的询问职责——追踪策略若由每个 skill 各自询问，答案必然分散。

## 问题

五个落点是产物的合法落点，但"落点在仓库里"不等于"该进版本控制"：

- 有的**必须跟踪**：`CONTEXT.md`、ADR、`init.sh`/CI 门禁、registry 状态文件。
- 有的**通常不该跟踪**：`.scratch/`（随任务/worktree 删除）。
- 第三方 skill 会把自己的产物倒进仓库，且**不区分追踪语义**。最典型的是上游的教学 skill——它明确"以当前目录作为有状态教学工作区"，在项目根目录直接运行，教学状态就落进了仓库。
- 有的产物**搬不动**：落点是 skill 自身的硬性规定（教学 skill 的「当前目录」不可配置），改造他人 skill 不现实——硬拒只会让用户绕开 harness，问题照旧存在。

真正的风险不是"跟不跟踪"本身，而是**没有唯一裁决者**：教学 skill 问一次、交接 skill 问一次、每个 skill 各问一次，结论分散、互相矛盾，于是同一个事实有了多个家（反例 #1 的变体）。

## 职责归属

| 角色 | 动作 |
|---|---|
| harness-creator | **独占**询问：探测 → 只问一次 → 落结论（`.gitignore` 为机制，AGENTS.md 为指针） |
| 其他 skill（上游系列，清单见 [Upstream Interlock](./upstream-interlock.md)） | **不询问**，读结论；产物落点见该文件的「产物落点视图」 |

## 五落点的默认追踪语义

| 落点 | 代表路径 | 默认 | 理由 |
|---|---|---|---|
| 临时材料 | `.scratch/` | 不跟踪 | 任务级材料，随任务/worktree 删除；进版本控制即制造过期事实来源 |
| 领域语言 | `CONTEXT.md` | 跟踪 | 跨会话、跨 worktree 共享；不跟踪则每个 worktree 从零重建 |
| 决策 | `docs/adr/` | 跟踪 | 只增不删的决策史，丢失不可逆 |
| 可执行约束 | `init.sh`、CI 配置 | 跟踪 | 违反即报错的门禁；不共享则验证口径漂移 |
| 状态与依赖 | `feature_list.json`、`progress.md`（tracker 模式为工单系统） | 跟踪 | registry 模式的仓内状态源；tracker 模式则在仓外，此处按缺失处理 |

## 对齐流程

### ① 探测（只读）

```bash
node <技能目录>/scripts/check-git-tracking.mjs --target /path/to/project --paths "CONSTRAINTS.md"
```

`--paths` 用于带上本次出现的落点外产物。脚本**不写盘**，输出五种状态：

| 状态 | 含义 |
|---|---|
| `tracked` | 已在 git 索引中（`git ls-files`）；目录落点下任一文件在索引即判定为跟踪 |
| `ignored` | 被 ignore 源命中（`.gitignore` / `.git/info/exclude` / `core.excludesFile`），脚本报出来源与行号 |
| `stray` | 存在，但既未提交也未忽略——**游离态**，最易漂移与误提交 |
| `absent` | 尚未产生，无从判定 |
| `unknown` | git 不可用或目标不是仓库 |

### ② 判定规则（机器可判的一律不问）

| 探测结果 | 判定 | 是否询问 |
|---|---|---|
| `tracked` | 跟踪 | 不问 |
| `ignored` | **视为用户已选择不跟踪** | 不问——"在 `.gitignore` 中列出"就是这个意思 |
| `stray` | 无法判定 | 🔴 必问 |
| `absent` | 按默认语义，产物产生时按默认执行 | 不问 |
| `unknown` | 无法判定 | 🔴 问一次（结论同样落 AGENTS.md） |

**「列入 `.gitignore`」的效力边界（关键）**：`.gitignore` 只作用于**未跟踪**路径。已提交的路径即使写进 `.gitignore` 也**仍然被跟踪**，脚本会报 `ineffective opt-out`。此时**不得**判为"不跟踪"：要么按跟踪处理，要么由用户决定 `git rm --cached`——该动作会改变他人工作树，本技能不代做，仅提示。

### ③ 只问一次（🔴 CHECKPOINT）

- 把探测表原样交给用户，**只请其裁决** `stray`、`unknown` 以及与默认相反的项；其余项直接给出结论，不逐条征询。
- 询问范围**包含第三方 skill 产物**（`--paths` 带入），提问时同步给出下方路由表的建议落点；对**已放行的豁免项**，只问其追踪状态，不重新讨论它该不该在落点之外（裁决结果已在豁免清单里）。
- harness **不代改 `.gitignore`**：给出确切行，经批准后再写。静默修改会让用户的表达失去可追溯性。

### ④ 落结论（不新增落点）

- **机制载体**：`.gitignore`（`.git/info/exclude`、全局 excludes 同等有效）。
- **文字载体**：AGENTS.md 中的一节，**只写指针与不变量**：

  ```markdown
  ## 产物追踪策略
  - 五落点的追踪状态以 `.gitignore` 与实际 git 索引为准（已对齐：<结论一句>）
  - 不跟踪的落点不得代为 `git add` / `git commit`
  - 第三方 skill 产物先路由进五落点；仅"自带硬约束"的放行，放行不治理，见下表

  ### 放行豁免清单（由产出 skill 自治理）
  | 路径 | 产出 skill | 性质 / 生命周期 | 用户裁决 | 追踪状态 | 复审触发 |
  |---|---|---|---|---|---|
  | `<path>` | `<skill>` | 教学状态 / 用完即删 | 原样保留 | 已 ignore | 用户改主意 / 该项越界读作事实 / 产物消失 |
  ```

- **豁免清单只登记、不路由**：写清"存在什么、归谁、跟不跟踪"，其内容**不进默认上下文**（启动工作流不默认读取豁免项）。一行写不清的，说明它已经是无主事实来源 → 收归五落点。**复审触发**列写清何时重看这一行；指向已消失产物的登记行由整理删除（见 [Housekeeping](./housekeeping-pattern.md)）。
- **「已询问过」的标记就是这一节**。后续会话读到即不再问。**绝不**另建 `git-tracking.json` 之类的独立文件记录结论——那是第六个落点（反例 #9）。

## 落点之外的第三方产物路由表

上游 skill 会往仓库里写五种落点之外的东西。判定顺序是**先路由、再放行、最后拒绝**：

1. **先路由**：产物落点可配置、可重定向 → 路由进五落点之一（多数情况，见下表）。
2. **受控放行**：产出 skill 自带**硬约束**（落点由它自身规定、不可改造）→ 放行，但 harness **不治理**、只审视，由用户裁决原样保留还是收归治理（见下节）。
3. **拒绝**：既路由不进、也援引不出硬约束 → 拒绝引入（黑名单 #9）。

**放行不是第六个落点**，也不放宽"每个事实只有一个家"——它只承认"skill 自用的私有工作区"可以停在落点之外，且必须登记、必须裁决、必须有追踪结论。

逐 skill 的**产物与落点映射**见 [Upstream Interlock](./upstream-interlock.md) 的「产物落点视图」——**名单只在那一处维护**，上游增删 skill 时改那里即可，本节不复述。本节只管判定顺序与放行机制。

三条通用规则（与具体 skill 无关，故留在本节）：

- 落点**可配置**的一律先路由；**能进 `init.sh`/CI 的约束**不留在仓库文件里，文件本体只作指针。
- 落在仓库**根目录且不属于任何落点**的产物必问一次，不静默放过（`CONSTRAINTS.md` 是典型）。
- **无持久产物**的 skill（只产出评审意见、对话结论）不需要落点，不要为它建文件。

## 受控放行（skill 自带硬约束时）

有些 skill 的落点是**它自己的硬性规定**，不是可配置项——最典型的是 `teach`：「以当前目录作为有状态教学工作区」写在其定义里，改造它、搬移它都不现实（他人的 skill 无法改造）。此时硬把产物路由进落点，只会让该 skill 失效或被弃用，而问题并不会消失，只是转入地下。

因此这类产物走**受控放行**：

| 要素 | 规定 |
|---|---|
| 放行 | 允许产物停在落点之外，harness 不要求搬移、不改写其内容与形态 |
| **不治理** | harness 不认领、不套用五落点格式（不把教学笔记改写成 `## Language`、不代为拆进 ADR/门禁）；该产物由**产出 skill 自身治理**，本技能不制定其规则 |
| **仍审视** | harness 必须登记该项（路径、产出 skill、性质、生命周期、owner），并回答"它是什么、会不会成为事实来源、在哪里"——放行不等于不看见 |
| **用户裁决** | 用户二选一：**原样保留**（skill 自治理，仅在本项目登记与追踪）或**收归治理**（路由进五落点，如教学笔记转 `.scratch/teach/`、长期知识转 `CONTEXT.md`） |
| **追踪结论** | 无论哪种裁决，该路径的 git 跟踪状态都必须明确——它作为额外产物进入一次性对齐的探测（`--paths`），`stray` 必问：提交，或加确切模式到 `.gitignore` |
| 不进默认上下文 | 登记项只写"存在什么、归谁"，其内容**不路由进代理默认读取**（启动工作流不默认读取豁免产物） |
| 可复审 | 用户改主意、skill 约束变化、或整理（housekeeping）时复审；**收归治理**随时可做，反向（已收归再放行）则需要重新裁决 |

### 放行的硬门槛（缺一即回落到"拒绝引入"）

1. **硬约束**：落点由产出 skill 自身规定，无法配置、无法重定向。**软约束一律先路由**，不得借"放行"绕过落点纪律。
2. **私有性**：该产物只服务产出 skill 自身的会话（如教学状态、临时台账），**不承担项目的状态、决策或领域语言职责**。
3. **可登记**：能用一行写清路径、owner 与生命周期；写不清说明它已经是无主的第六个事实来源。

### 一旦越界即收归治理

放行项只要开始承担项目事实职责——代理要从它读状态、它是决策依据、或它的术语被代码引用——就**不再属于"私有工作区"**，必须收归五落点（状态→注册表/工单、决策→ADR、术语→`CONTEXT.md`、约束→门禁）。放行只容忍"skill 自用"；容忍不了"没有主人的事实"。


### `teach` 特别条款

`teach` 是本机制的重点对象，因为它天然违反"落点唯一"，且它的约束是**硬的**（「当前目录」写在技能定义里，不可配置）：

1. **首选软路由**：以 `.scratch/teach/` 为 cwd 运行——这个动作在本技能的可控范围内（改变的是调用时的工作目录，不是改造 teach 本身），优先走这条。
2. **不可重定向时受控放行**：若实际无法重定向（用户就是在仓库根目录用 teach、或教学对象本身是仓库内容），则受控放行：登记豁免、由用户裁决原样保留或收归治理，并给出追踪结论。**不因为它是 root 目录下的教学状态就拒绝**——拒绝只会让用户放弃 harness，问题照旧存在。
3. **不治理**：不论哪种裁决，harness 都不替 teach 规定其工作区内部结构与格式；这是 teach 自己的事。
4. **不重复询问**：`teach` 不自行询问其工作区是否纳入版本控制——结论已由本技能一次性落定，它只读 AGENTS.md。
5. **不污染模式探测**：`teach`（以及 `research`/`handoff`）按需写入的残留目录，**不得**被读作 matt 的"本地 markdown 工单已在用"信号。tracker 模式探测以 `docs/agents/`、`CONTEXT.md`、ADR 为准。
6. **不得成为事实来源**：教学笔记一旦被代理当作项目知识读取（例如被写进 AGENTS.md 路由、被代码引用），即越界 → 收归治理（长期知识→`CONTEXT.md`，任务材料→`.scratch/`）。

## 何时可以重新询问

- 用户显式要求变更追踪策略，或对某项豁免改主意（原样保留 ⇄ 收归治理）。
- 出现**新的**落点外产物（探测为 `stray`）——只问该产物，不重问已定的五落点。
- 豁免项越界（开始承担状态/决策/术语职责）、或产出 skill 的约束发生变化——复审**该**豁免项。
- 其余情况一律不问：读 AGENTS.md 结论。

## 反例

| # | 反模式 | 为什么不要做 | 替代做法 |
|---|---|---|---|
| 1 | 每个第三方 skill 各自询问追踪策略 | 答案分散、互相矛盾，同一事实多个家 | harness-creator 独占询问，其余 skill 只读结论 |
| 2 | 把结论写成仓内独立文件（如 `.git-tracking.json`） | 制造第六个落点，他人 skill 无法改造 | 机制落 `.gitignore`，指针落 AGENTS.md 一节 |
| 3 | 把已提交的落点写进 `.gitignore` 就判为"不跟踪" | gitignore 对已跟踪文件无效，跟踪状态未变——结论是假的 | 报 `ineffective opt-out`，由用户裁决是否 `git rm --cached` |
| 4 | 代用户静默修改 `.gitignore` | 用户表达不可追溯，且可能覆盖既有规则 | 给确切行 + 🔴 CHECKPOINT 批准后写入 |
| 5 | 让 `teach` 在仓库根目录新建教学工作区，且不登记、不裁决 | 落点外产物隐身：没人知道它是什么、归谁、跟不跟踪 | 首选重定向到 `.scratch/teach/`；不可重定向则受控放行（登记 + 用户裁决 + 追踪结论） |
| 6 | 把 `stray`（游离态）当"不跟踪"处理 | 既未提交也未忽略，是最易漂移与误提交的状态 | 必须裁决：提交，或加确切模式到 `.gitignore` |
| 7 | 用 `absent` 反推用户意图 | 尚不存在的东西没有意图；猜错会把结论写反 | 按默认语义执行，产物出现时若与默认冲突再问 |
| 8 | 把"放行"理解成"不用管" | 产物隐身正是第六事实来源的温床，反例 #9 的危害一分未减 | 放行 = 登记 + 裁决 + 追踪结论：**不治理 ≠ 不看见** |
| 9 | 放行后 harness 代为改造该产物（搬进落点、改写成自己的格式） | 越界治理他人 skill 的地盘，产物与 skill 双双失效 | 不治理：由产出 skill 自治理；用户裁决"收归治理"时才由本技能接管 |
| 10 | 放行项被代理当作项目知识读取 | 无主事实来源回流，落点纪律失效 | 登记项不进默认上下文；一旦承担事实职责即收归五落点 |
| 11 | 用"skill 有硬约束"当借口，把可配置的产物也放行 | 软约束本可路由，放行口子一开，落点纪律整体失效 | 硬约束是门槛不是修辞：能配置能重定向的一律先路由 |

## 异常与边界

| 触发条件 | 一线修复 | 仍失败兜底 |
|---|---|---|
| git 不可用或目标不是仓库 | 脚本降级为 `unknown` 并显式提示 | 改为一次性询问全表，结论仍落 AGENTS.md |
| `.git/info/exclude` 或全局 excludes 命中 | 与 `.gitignore` 同效，脚本报出来源与行号 | 仍视为"不跟踪"，不重复询问 |
| 目标不是仓库根（worktree、子目录） | 脚本报出 git toplevel 并按该索引探测 | 结论跟随主仓库，不在每个 worktree 重问 |
| 目录落点下仅部分文件被跟踪 | 任一文件在索引即判 `tracked`，脚本列出样例文件 | 由用户决定是否 `git rm --cached`，本技能不代做 |
| `.gitignore` 只有目录级通配（如 `*`） | `check-ignore` 仍给出命中来源与模式 | 询问一次确认意图，不把通配当逐项裁决 |
| 用户拒绝裁决 `stray` | 保持 `stray` 并写入 AGENTS.md 待办 | 不代替用户决定；审计时标为未决项 |
| 结论与 init.sh/CI 冲突（门禁脚本落在被忽略路径） | 优先保证门禁可被跟踪，提示调整 `.gitignore` | 门禁无法共享即降级为文本约束并显式标记 |
| 放行项产生 `.gitignore` 未覆盖的新文件 | 每次探测都用 `--paths` 带上豁免清单中的路径 | 出现 `stray` 即问一次，不静默忽略 |
| 豁免项同时被两个 skill 写入 | 逐 skill 分行登记 | 归不到单一 owner 即收归五落点 |
| 豁免项已被删除或已迁走 | 整理（housekeeping）时删掉该登记行 | 不保留指向已消失产物的登记 |
| 用户拒绝裁决放行项（既不放行也不收归） | 保持未决，写入 AGENTS.md 待办 | 审计时标为未决项；不代替用户决定，也不静默放行 |

## 与既有规则的关系

- 反例 #9（落点之外）：本机制是该条的执行细则——**先路由、再受控放行、最后拒绝**，且放行项仍须有追踪结论。落点合法不代表追踪状态已定。
- matt 单一写入者分区：`.scratch/` 由使用方按需写入，本机制**不预建**该目录，只约定其追踪状态。
- 「文档治理」：第三方教学/研究类产物若确需长期保留，按文档治理指定 owner 并进 AGENTS.md 路由；豁免清单只登记"skill 自用"的私有工作区，不承担文档治理职责。
