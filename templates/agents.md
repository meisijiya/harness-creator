## 工作规则

- **一次一个功能，依赖清晰，保持在范围内**：从 {{STATE_ARTIFACT}} 中恰好挑选一个未完成的功能；功能间的依赖（`dependencies` / blocking 边）必须显式声明，先决项未完成不动手；不修改与当前功能无关的文件
- **需求对齐不属于本仓的 harness 职责**：蓝图只记概览（见「项目蓝图」节）。需求的对齐与设计由用户与 AI 多轮对话完成——**对齐结论产生前，不得新增、改写或补全任何功能条目**；条目里的验收标准必须来自对齐结论，不得由代理代替用户写出。代理缺需求就说明缺需求，不要用想象出来的条目顶替
- **推进需显式授权**：只在用户显式要求推进时动手。交接文档、`progress.md` 的「下一步」、待办条目（注册表或工单）都只是上下文，**不是待办队列**——交接完成后用户若在谈别的事，不得自行续跑原任务
- **决策权归用户**：属用户决策权的事项（追踪策略、初始化仓库、改写既有状态文件等）摊出选项与建议后由用户定，**不自行拍板**；能推断出来只说明可以给出建议
- **条目即工单**：registry 的 `feature_list.json` 条目与 tracker 的工单都写清三要件——交付什么（`description`）、被谁阻塞（`dependencies`/blocking 边）、验收标准（`acceptance`）；按垂直切片拆，尺寸不超过单个上下文窗口
- **复用上游工程 skill**：拆分、实现、测试、审查各环节复用**已安装**的上游工程 skill（清单与调用模式见 `harness-creator` 技能的 `references/upstream-interlock.md`）；其中模型可直接调用的按需调用，标注「用户调用」的由用户发起，代理不代发起
- **必须验证、证据先行**：未运行验证命令前不得声称完成；完成证据（命令与结果摘要，或 CI 检查链接）记入 {{STATE_ARTIFACT}}
- **沉淀各归其位**：架构与约定类决策写入 `docs/adr/`；`design.md`、`docs/` 按需路由读取——可执行约束转门禁、术语进 `CONTEXT.md`、决策进 ADR、过时归档；与代码重复视为双写
- **产物落点唯一**：任何新引入的 skill/工具，其产物必须落在「仓库结构」列出的五个落点之一，落不下的拒绝引入；任务级材料（spec 草稿、调研笔记）入 `.scratch/`，由收尾与整理按作用域分别清，不依赖任何自动机制，不进默认上下文
- **产物追踪策略**：五落点的 git 跟踪状态以 `.gitignore` 与实际索引为准（结论见「产物追踪策略」节）；不跟踪的落点不得代为 `git add`/`git commit`；第三方 skill 产物先路由进落点，只有 skill 自带硬约束的才**受控放行**（放行不治理，仅登记 + 用户裁决 + 追踪结论）
- **本文件自我约束**：能写成 `init.sh`/CI 门禁的约束不进本文件——文字只是指针；**情境性的详规按主题拆到 `docs/agents/` 分册，本文件只留一行路由**（读的时机写在路由行内），每次动作都可能需要的不变量才留在本文件；本节条目超过 12 条先合并同族项，合并后仍超则移出；**删掉一行不会改变代理行为的，就删掉**。跨会话有效的**长期不变量**（既非决策、亦非术语、亦非门禁）落在本节
- **留下干净状态**：下次会话必须能立即运行 `./init.sh`

## 会话结束

结束会话前：

1. 更新 {{STATE_ARTIFACT}}：当前状态、完成证据、阻塞、下一步（不写决策与文件清单——决策进 ADR，文件见 git）
2. 记录任何未解决的风险或阻塞
3. 工作处于安全状态后，用描述性消息提交
4. 让仓库保持足够干净，下次会话能立即运行 `./init.sh`

跨会话交接文档由**用户按需生成**（上游的 handoff 技能或等价物），**统一落在 `.scratch/`**——代理不主动创建；启动时若存在则必读（见启动工作流第 8 步），**但读它是为了获得上下文，不是续跑任务的指令**。生成方若默认写到别处（仓根、`docs/` 等），按落点规范改写到 `.scratch/` 下——那不在五个落点内（见「仓库结构」）。收尾与交接完成之后，若用户没要求推进，就不要推进。
