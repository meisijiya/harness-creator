# 技术栈

> **按需读**，不是常驻指令文件：只在改依赖、改构建、或判断某条命令该用哪个工具时打开。
>
> 下面每一格要么写出**证据**（从哪个文件读到的），要么写「待补」。没有第三种状态。

## 检测到的（附证据）

- 包清单 / 包管理器：{{DETECTED_MANIFEST}}
- 检测到的栈标识：{{DETECTED_STACK}}

「检测到的栈标识」是目录里文件名的机械结果，不是一份技术选型结论：它说得出
「这里有 `go.mod`」，说不出「这个项目为什么用 Go 而不是 Rust」。

## 待补（尚无证据）

- 数据库 / 存储：待补
- 测试框架与运行方式：待补
- 构建、打包与部署：待补
- CI 跑在什么上面：待补

这些留「待补」不是因为本技能不知道，是因为**检测不到**：包清单里没有声明、也没有配置文件
说明，就说明还没有人把它写下来。由「这是个后端项目」推出「它用 Postgres」是推断，不是证据。

## 怎么维护这一份

用户陈述变了才改。「待补」变成有据可依的事实时，把证据补进上面那一节；
证据消失（文件删了）时，把它退回「待补」，不要留着一条已经过期的断言。

## 一条硬边界

**技术栈不得用来反推项目使命。** 「用了 React」推不出「这是一个编辑器」，
「有 Dockerfile」推不出「它要部署到哪」。`mission.md` 的每一格只能由用户陈述填入，
本文件里的任何一格都不能作为它的输入。

确实需要写进来时，由用户陈述补进 `mission.md`，不是由本文件推导过去。
