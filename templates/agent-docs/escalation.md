# 升级处理（详规）

`{{AGENT_FILE_NAME}}` 的「升级处理」节只留触发条件；本文件写各情形的判据与去处。**遇到下列情形之一时读**——不进默认阅读路径。

## 架构决策

- 先查 `docs/adr/` 与项目架构文档（如存在），看是否已有定论
- 无定论 → 问用户，不自行拍板
- 定论产生后 → 写入 `docs/adr/`（决策进 ADR，不进进度日志）

## 需求不清

- 先查产品/需求文档与 `CONTEXT.md`（如存在）
- 仍不清 → 问用户；**不代替用户写验收标准**，也不新增功能条目（见「工作规则」的「需求对齐」条）
- 缺需求就说明缺需求，不用想象出来的条目顶替

## 测试反复失败

- 更新 {{STATE_ARTIFACT}} 的当前状态与阻塞
- 标记为需要人工评审；**不在未定位根因前反复改代码**
- 若证明是基线问题：先修基线，再继续新工作

## 范围模糊

- 重读 `{{AGENT_FILE_NAME}}` 的「完成定义」，按验收标准逐条核对
- 仍模糊 → 按「需求不清」路径处理

## 通用边界

- 任何情形下都不静默跳过或降级：先把问题显式写进 {{STATE_ARTIFACT}}，再选择路径
- 属用户决策权的事项摊出选项与建议后由用户定，不自行拍板
