# 产物追踪策略（详规）

`{{AGENT_FILE_NAME}}` 的「产物追踪策略」节只写结论与不变量；本文件是它的详规。**在遇到产物落点归属、第三方产物或追踪裁决问题时读**——不进默认阅读路径。

## 五个落点的默认追踪语义

| 落点 | 代表路径 | 默认 | 理由 |
|---|---|---|---|
| 临时材料 | `.scratch/` | 不跟踪 | 任务级材料，由收尾与整理按作用域分别清；进版本控制即制造过期事实来源 |
| 领域语言 | `CONTEXT.md` | 跟踪 | 跨会话、跨分支共享；不跟踪则每开一个工作副本都要从零重建 |
| 决策 | `docs/adr/` | 跟踪 | 只增不删的决策史，丢失不可逆 |
| 可执行约束 | `init.sh`、CI 配置 | 跟踪 | 违反即报错的门禁；不共享则验证口径漂移 |
| 状态与依赖 | registry：`feature_list.json`、`progress.md`；tracker：工单系统 | 跟踪 | registry 的仓内状态源；tracker 在仓外，按缺失处理 |

默认只是起点：**实际状态以 `.gitignore` 与实际 git 索引为准**。

## 只读探测

```bash
node <harness-creator 技能目录>/scripts/check-git-tracking.mjs --target .
```

脚本不写盘，输出五种状态：

| 状态 | 含义 | 是否询问 |
|---|---|---|
| `tracked` | 已在 git 索引中（`git ls-files`） | 不问 |
| `ignored` | 被 ignore 源命中（`.gitignore` / `.git/info/exclude` / 全局 excludes） | 不问——列入忽略即"用户已选择不跟踪" |
| `stray` | 存在，却既未提交也未忽略（游离态） | 🔴 必问 |
| `absent` | 尚未产生，按默认语义执行 | 不问 |
| `unknown` | git 不可用或非仓库 | 🔴 问一次 |

## 裁决规则

- **只问一次**：询问由 `harness-creator` 在初始化时完成；此后本文件与 `{{AGENT_FILE_NAME}}` 的结论即权威，代理与第三方 skill 都只读不问。
- **`.gitignore` 只对未跟踪路径有效**：已提交的路径即使写进 `.gitignore` 也仍被跟踪（`ineffective opt-out`）。此时**不得**判为"不跟踪"——要么按跟踪处理，要么由用户决定 `git rm --cached`，代理不代做。
- **不代改 `.gitignore`**：给出确切行，经用户批准后才写；静默修改会让用户的表达失去可追溯性。

## 落点之外的第三方产物：先路由、再放行、最后拒绝

1. **先路由**：产物落点可配置、可重定向 → 路由进五落点之一（多数情况）。
2. **受控放行**：产出 skill 自带**硬约束**（落点由它自身规定、不可改造，如教学类 skill 的"以当前目录为工作区"）→ 放行，但**不治理**其内容与形态（由产出 skill 自治理），只登记 + 用户裁决 + 追踪结论。
3. **拒绝**：既路由不进、也援引不出硬约束 → 拒绝引入。

放行不是第六个落点，也不等于"不用管"：**登记、裁决、追踪结论三要素缺一即回落为拒绝**。放行项一旦被代理当作项目知识读取（承担状态、决策或术语职责），立即收归五落点。
